# Cursor Prompt: Build the Nova PostgreSQL Database Schema, TypeORM Entities, Migrations, and Seed System

You are working in a Node.js + TypeScript backend project using TypeORM 0.3+ with PostgreSQL.

Build a complete, production-ready database layer for the Nova application. This prompt is fully self-contained. Do not ask for, reference, or depend on any Excel workbook or external schema document. Everything needed to implement the database schema and seed data is included below.

## Core Requirements

Implement:

1. A full PostgreSQL schema using TypeORM entities.
2. A clean initial migration.
3. Idempotent seed scripts.
4. Docker Compose startup behavior so that `docker compose up` creates the DB, runs migrations, seeds the DB, and then starts the API.
5. Enough seed data for the application to be immediately usable for users, RBAC, customers, products, sales, customer issues, issue action workflows, SOPs, conversations, and messages.

Do not use `synchronize: true`.

Use explicit migrations.

Use snake_case table and column names in PostgreSQL.

Use camelCase property names in TypeScript.

Use TypeScript strict typing wherever possible.

## Important Naming and Typo Corrections

The final implementation must use the corrected names below. Do not use the typo variants anywhere in table names, entity properties, migration names, seed object keys, relation names, or comments unless explicitly documenting that they were corrected.

- `Coversations` -> `Conversations`

Authentication will be handled elsewhere. The DB user records are application user profile records only.

The seed data below intentionally excludes passwords.

## Idempotency Rules

1. Users: upsert by `email`.
2. Roles: upsert by `name`.
3. Permissions: upsert by `name`.
4. User roles: insert missing composite pairs only.
5. Role permissions: insert missing composite pairs only.
6. Customers: upsert by `email`.
7. Products: upsert by `name`.
8. SOPs: upsert by `name`.
9. SOP details: upsert by `(sopId, version)`.
10. Sales: upsert by deterministic `id`.
11. Products sold: upsert by `(saleId, productId)`.
12. Customer issues: upsert by deterministic `id`.
13. Issue actions: upsert by deterministic `id`.
14. Issue action dependencies: insert missing composite pairs only.
15. Action comments: upsert by deterministic `id`.
16. Conversations: upsert by deterministic `id`.
17. Messages: upsert by deterministic `id`.

# Docker Compose Requirements

Implement Docker Compose so `docker compose up` does the following:

1. Starts Postgres.
2. Waits for Postgres to become healthy.
3. Runs migrations.
4. Runs the seed script.
5. Starts the API only after DB initialization succeeds.

Preferred Compose pattern:

- `postgres` service.
- `db-init` one-shot service running `npm run db:init`.
- `api` service depending on `db-init` with `condition: service_completed_successfully`.

Use a Postgres healthcheck:

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U nova -d nova"]
  interval: 5s
  timeout: 5s
  retries: 20
```

Example Compose structure to implement or adapt:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: nova-postgres
    environment:
      POSTGRES_DB: nova
      POSTGRES_USER: nova
      POSTGRES_PASSWORD: nova_password
    ports:
      - "5432:5432"
    volumes:
      - nova-postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U nova -d nova"]
      interval: 5s
      timeout: 5s
      retries: 20

  db-init:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: nova-db-init
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      DATABASE_URL: postgres://nova:nova_password@postgres:5432/nova
      DB_SSL: "false"
      DB_LOGGING: "false"
      SEED_RESET: "false"
    command: sh -c "npm run db:init"
    restart: "no"

  api:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: nova-api
    depends_on:
      db-init:
        condition: service_completed_successfully
    environment:
      DATABASE_URL: postgres://nova:nova_password@postgres:5432/nova
      DB_SSL: "false"
      DB_LOGGING: "false"
    ports:
      - "3000:3000"
    command: npm run start:dev

volumes:
  nova-postgres-data:
```

If the local Compose version does not support `service_completed_successfully`, implement a robust alternative startup script that waits for Postgres, runs migrations and seed idempotently, and then starts the API.
